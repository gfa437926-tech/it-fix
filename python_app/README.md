# IT Fix — نسخة Python المستقلة

هذه نسخة مستقلة من برنامج جرد الأصول، ولا تستبدل تطبيق React/Firebase الحالي ولا تتصل به تلقائياً. الكود موجود في مجلد `python_app/`.

## ما يعمل في النسخة الحالية

- واجهة سطح مكتب عربية باتجاه RTL باستخدام Tkinter.
- إضافة الأصول وتعديلها والبحث والتصفية حسب الحالة.
- منع تكرار الرقم التسلسلي بعد تحويله إلى أحرف كبيرة وإزالة المسافات.
- إدارة المكاتب والمواقع.
- نقل الأصل بين المكاتب مع تسجيل الحركة.
- استبعاد الأصل مع إلزامية السبب، ومنع استبعاد أصل في عهدة أو صيانة.
- لوحة مؤشرات مختصرة للأصول والمكاتب.
- استيراد XLSX مع التحقق من الصفوف وتقرير الأخطاء.
- تصدير XLSX عربي، مع حماية الخلايا النصية التي قد تُفسر كصيغ Excel.
- سجل حركات وتدقيق لعمليات الأصول الأساسية.
- بطاقات عهدة بمراحل انتظار الاعتماد، الاعتماد، الرفض والإرجاع.
- ربط أجهزة العهدة ببطاقة الموظف، مع تغيير حالة الأصل فقط بعد الاعتماد.
- طلبات صيانة مع أولوية وحالة وفني وتكلفة ونتيجة الإصلاح، وإرجاع الأصل إلى حالته السابقة عند الإغلاق.
- مخزون قطع غيار مع حد أدنى وتنفيذ صرف مرتبط بطلب صيانة؛ تُخصم الكمية وتُضاف التكلفة ضمن المعاملة نفسها.
- سجل فواتير شراء مرتبط بالأصل، مع رقم فاتورة ومورد وتاريخ شراء وقيمة وضمان، ومنع تكرار الفاتورة للأصل نفسه لدى المورد نفسه.
- إرفاق مستندات الأصول وفتحها من داخل البرنامج؛ الأنواع المدعومة PDF وPNG وJPG وTXT، وحد الحجم 20 ميغابايت، مع التحقق من ترويسة الملف وحفظه باسم عشوائي داخل مجلد البيانات وتسجيل عملية الإرفاق في سجل التدقيق.

- تسجيل دخول محلي عند كل تشغيل، مع إعداد مدير النظام الأول من شاشة البدء دون كلمة مرور افتراضية.
- تخزين كلمات المرور باستخدام scrypt مع ملح عشوائي، وحد أدنى 12 محرفاً، وقفل مؤقت لمدة 10 دقائق بعد خمس محاولات فاشلة متتالية.
- إدارة المستخدمين وتفعيل الحسابات وإيقافها متاحة لمدير النظام فقط؛ الأدوار الحالية هي مدير النظام ومشغل الأصول، وكلمة المرور الأولية للحساب الجديد يجب تغييرها عند أول دخول.
- سجل تدقيق قابل للبحث والتصفية حسب الكيان والعملية، مع تصدير CSV عربي UTF-8 وحماية من صيغ Excel/CSV.
- تقرير إداري شامل بصيغة XLSX مع صفحات الملخص والأصول والمكاتب والعهدة وبنودها والصيانة وقطع الغيار والمشتريات والمرفقات والحركات والتدقيق. تبويبا التدقيق والتقرير الشامل يظهران لمدير النظام فقط.
- ورقة تحليل إضافية داخل التقرير الشامل تقارن الأصول وحالاتها وقيم المشتريات وتكاليف الصيانة وقطع الغيار حسب المكتب، مع إظهار الأصول غير المرتبطة بمكتب ضمن مجموعة مستقلة.

## ما لا يزال قيد الاستكمال

- صلاحيات تفصيلية حسب المكتب/المستودع والوظيفة؛ دور مشغل الأصول يمنح حالياً صلاحيات تشغيلية عامة داخل قاعدة البيانات المحلية.
- تقارير تحليلية متقدمة بفلاتر زمنية ومقارنات وتكاليف حسب الجهة/المكتب.
- المزامنة الخارجية والربط بخدمات Google بصورة مستقلة في نسخة Python.
- اختبار دورة كاملة على قاعدة بيانات إنتاجية مشتركة، واعتماد آلية نسخ احتياطي واستعادة ومراجعة تشغيلية نهائية.

**ملاحظة حول المرفقات:** تخزين الملفات في نسخة Python محلي على الجهاز أو الخادم الذي يشغّل التطبيق، وليس في Firebase Storage أو Supabase Storage. التحقق الحالي يضبط الامتداد والتوقيع والحجم ولا يمثل فحصاً لمكافحة البرمجيات الخبيثة؛ لذلك يجب استقبال الملفات من مصادر موثوقة وفحصها بسياسة المؤسسة قبل تداولها.

## تشغيل سريع على Windows — دون Docker

1. ثبّت Python 3.11 أو أحدث.
2. افتح PowerShell داخل مجلد المستودع.
3. نفّذ:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
py -m pip install -r python_app\requirements.txt
py -m python_app.app
```

عند عدم وجود ملف `.env` أو متغير `DATABASE_URL`، ينشئ التطبيق قاعدة SQLite محلية تلقائياً في:

`python_app/data/itfix_assets.db`

في أول تشغيل تظهر شاشة إعداد مدير النظام الأول. اختر اسم المستخدم والاسم الظاهر وكلمة مرور قوية (12 محرفاً على الأقل). لا توجد بيانات دخول افتراضية. في كل تشغيل لاحق تظهر شاشة تسجيل الدخول. بعد إنشاء مستخدم جديد من حساب المدير، يجب عليه تغيير كلمة المرور الأولية عند أول دخول.

هذا الوضع يتيح تشغيل البرنامج وتجربة الوظائف فوراً، ولا يحتاج إلى Docker أو خادم قاعدة بيانات منفصل.

## قاعدة PostgreSQL محلية من دون Docker

يمكن تثبيت PostgreSQL كخدمة Windows عادية، ثم إنشاء قاعدة ومستخدم للتطبيق من خلال `psql`:

```sql
CREATE ROLE itfix_app LOGIN PASSWORD 'ضع-كلمة-مرور-قوية-هنا';
CREATE DATABASE itfix_assets OWNER itfix_app;
```

انسخ `.env.example` إلى `.env` داخل مجلد `python_app`، ثم اضبط:

```dotenv
DATABASE_URL=postgresql+psycopg://itfix_app:كلمة_المرور@127.0.0.1:5432/itfix_assets
AUTO_CREATE_SCHEMA=false
```

بعد مراجعة نماذج الجداول في `python_app/models.py`، أنشئ الجداول صراحةً:

```powershell
py -m python_app.init_database --confirm-create-schema
py -m python_app.app
```

لا تُخزّن كلمة المرور في Git، ولا تضع ملف `.env` في المستودع.

## ما المقصود بـ Supabase دون Docker؟

التطبيق يستخدم SQLAlchemy وموصل psycopg، لذلك يستطيع الاتصال بمحرك PostgreSQL محلي مثبت مباشرة، أو بعنوان اتصال PostgreSQL لمشروع Supabase مستضاف. عند الاتصال بخادم خارجي يجب استخدام TLS:

```dotenv
DATABASE_URL=postgresql+psycopg://USER:PASSWORD@HOST:5432/postgres?sslmode=require
AUTO_CREATE_SCHEMA=false
```

**تنبيه مهم:** اتصال PostgreSQL هنا يعني استخدام قاعدة البيانات فقط؛ لا تشغّل نسخة Python خدمات Supabase Auth أو Storage أو REST API. شاشة الدخول الحالية محلية ومخزنة في جدول app_users، ولا تستخدم جلسات Firebase ولا تمنح صلاحيات على خدمات React/Firebase. لذلك لا تعتبرها بديلاً عن نظام هوية مركزي عند تشغيل عدة أجهزة أو فروع عبر الشبكة.

عند الاتصال بقاعدة خارجية مع AUTO_CREATE_SCHEMA=false يتحقق البرنامج من وجود جميع جداول نسخة Python قبل التشغيل، ولا ينشئ مخططاً أو يغيّره تلقائياً. في SQLite تُفعّل مفاتيح العلاقات الخارجية ومهلة انتظار الكتابة.

## إنشاء ملف Windows EXE

يوجد مسار بناء تلقائي في GitHub Actions باسم **Python Asset Inventory Windows Build**، وينتج ملف سطح المكتب `ITFix-Asset-Inventory.exe` وأداة سطر أوامر مستقلة `ITFix-Restore-Backup.exe` مرفقاً معهما دليل التشغيل وملف الإعداد النموذجي. يمكن تنزيل artifact باسم `ITFix-Asset-Inventory-Windows` بعد نجاح البناء.

في النسخة المجمّعة، تحفظ قاعدة SQLite المحلية في مجلد المستخدم:

`%LOCALAPPDATA%\\ITFix\\data`

وبذلك لا تضيع البيانات عند إعادة تشغيل ملف EXE المؤقت ولا تحتاج إلى صلاحيات الكتابة داخل مجلد Program Files. تحفظ مرفقات الأصول داخل المجلد الفرعي documents في مجلد البيانات نفسه؛ ضمّن قاعدة البيانات ومجلد المرفقات معاً عند إجراء نسخة احتياطية.

## النسخ الاحتياطي

من تبويب **التقارير الشاملة** يستطيع مدير النظام اختيار **نسخة احتياطية كاملة**. يتضمن ملف ZIP:

- لقطة متسقة من قاعدة البيانات: ملف SQLite، أو ملف PostgreSQL بصيغة pg_dump المخصصة.
- جميع مرفقات الأصول المخزنة محلياً داخل مجلد `documents`.
- ملف `manifest.json` يحوي وقت الإنشاء ونوع قاعدة البيانات وأحجام الملفات وبصمات SHA-256 للتحقق من سلامة المحتويات.

عند استخدام PostgreSQL يجب تثبيت أداة `pg_dump` وإتاحتها في PATH. إذا لم تكن موجودة، ستظهر رسالة واضحة ولن يدّعي التطبيق أن النسخة اكتملت.

**تنبيه أمني:** ملف ZIP غير مشفّر بكلمة مرور لأنه يحتوي قاعدة البيانات وكلمات المرور المشتقة وسجلات المستخدمين ومرفقات الأصول. احفظه على وسيط أو مجلد مشفّر ومقيّد الصلاحيات، ولا ترسله عبر قنوات غير آمنة. النسخة الاحتياطية تُنشأ ولا تُستعاد من داخل الواجهة حالياً؛ استعادة البيانات إجراء إداري يدوي ويجب أن تتم بعد إيقاف التطبيق وأخذ نسخة من الحالة الحالية.

## التحقق من النسخة واستعادتها (SQLite)

لاستعادة نسخة SQLite، أوقف جميع نوافذ IT Fix أولاً، ولا تستعد نسخة فوق قاعدة مستخدمة من التطبيق. نفّذ من مجلد المستودع:

```powershell
# تحقق من سلامة الأرشيف دون تعديل البيانات
.\\ITFix-Restore-Backup.exe "C:\\Backups\\ITFix-Backup.zip" --verify-only

# أغلق IT Fix بالكامل، ثم نفّذ الاستعادة
.\\ITFix-Restore-Backup.exe "C:\\Backups\\ITFix-Backup.zip" --confirm-restore
```

للتشغيل من مصدر Python بدلاً من ملف EXE:

```powershell
py -m python_app.restore_backup "C:\\Backups\\ITFix-Backup.zip" --verify-only
py -m python_app.restore_backup "C:\\Backups\\ITFix-Backup.zip" --confirm-restore
```

الأمر الأول يتحقق من سلامة ZIP وبصمات SHA-256 لقاعدة البيانات والمرفقات دون تعديل أي شيء. الأمر الثاني يفحص سلامة SQLite ومخطط الجداول، وينشئ أرشيف أمان تلقائياً من الحالة الحالية قبل الاستبدال، ثم يستعيد قاعدة البيانات ومجلد المرفقات. لا يكتب فوق أرشيف أمان موجود؛ اختر مساراً آخر عبر `--safety-backup` عند الحاجة.

الاستعادة الآلية متاحة لقاعدة SQLite فقط. عند استخدام PostgreSQL، تحقّق من ملف الأرشيف ثم استخدم أدوات PostgreSQL المناسبة `pg_restore` بعد مراجعة نسخة الأمان وخطة الاستعادة؛ لا تنفّذ استعادة PostgreSQL على قاعدة إنتاج دون موافقة مسؤول قاعدة البيانات.

## اختبارات المطور

```powershell
py -m pip install pytest
py -m compileall -q python_app
py -m pytest python_app/tests
```

الاختبارات الحالية تستخدم SQLite مؤقتة داخل الذاكرة، ولا تتصل ببيانات المستخدم أو قاعدة خارجية.
