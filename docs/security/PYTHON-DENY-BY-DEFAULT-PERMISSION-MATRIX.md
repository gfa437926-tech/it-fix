# IT Fix — مصفوفة التفويض الدقيقة (Deny by Default)

هذه الوثيقة تحدد السياسة المستهدفة للتطبيق المكتبي Python. لا تنشئ جداول ولا تنفذ أي تعديل على قاعدة البيانات. لا تُفعّل الأدوار المقترحة تلقائياً قبل اعتماد grants موثوقة للمكاتب والمستودعات.

## 1. قرار التفويض

يُسمح بالعملية فقط إذا تحققت الشروط كلها:
1. الحساب موجود ونشط بعد إعادة التحقق من قاعدة البيانات.
2. الدور معروف وممنوح له الإذن المحدد للكيان والعملية.
3. الكيان يقع ضمن نطاق المكتب المصرح به، إذا كانت العملية مرتبطة بمكتب.
4. الكيان يقع ضمن نطاق المستودع المصرح به، إذا كانت العملية مرتبطة بمستودع.
5. في النقل، يجب السماح بالمصدر والوجهة كلٌّ على حدة.
6. أي إذن أو نطاق مفقود أو غير معروف يعني الرفض.

لا يجوز بناء الصلاحيات أو النطاق من قيم واجهة المستخدم أو طلب HTTP أو اختيار ComboBox.

## 2. مصفوفة الأدوار المستهدفة

الرموز: R قراءة، C إنشاء، U تعديل، D حذف، T نقل، A اعتماد/إرجاع، M إدارة، X تصدير/تقارير. الشرطة تعني منعاً.

| الكيان / العملية | admin | office_manager | warehouse_keeper | asset_operator | viewer |
|---|---|---|---|---|---|
| الأصول | R/C/U/D/T/retire | R/C/U/T | R/U/T داخل مستودعاته | R/C/U داخل نطاقه | R |
| العهد | R/C/A/return | R/C/A/return | R | R/C | R |
| الصيانة | R/C/U | R/C/U | R | R/C | R |
| قطع الغيار | R/C/U/D | R داخل المكتب | R/C/U داخل مستودعه | R | R |
| المشتريات | R/C/U/approve | R/C ضمن المكتب | — | — | R |
| المرفقات | R/upload/delete | R/upload ضمن المكتب | R/upload ضمن المستودع | R/upload ضمن النطاق | R |
| التقارير | R/export | R/export ضمن المكتب | R ضمن المستودع | R ضمن النطاق | R |
| المستخدمون والأدوار | M | — | — | — | — |
| سجل التدقيق | R | R ضمن النطاق | — | — | — |
| النسخ الاحتياطي والاستعادة | M | — | — | — | — |

هذه مصفوفة تصميمية قابلة للمراجعة، وليست تفويضاً فعالاً في قاعدة البيانات. يجب اعتماد صلاحيات الموافقة والحذف والشراء والتصدير على وجه الخصوص قبل تشغيلها.

## 3. أبعاد النطاق

- office_manager: المكتب/المكاتب المربوطة به صراحة، والمستودعات التي ثبت ارتباطها بهذه المكاتب.
- warehouse_keeper: المستودعات المربوطة به فقط؛ لا يحصل تلقائياً على كل أصول المكتب.
- asset_operator: نطاق مكتب/مستودع محدد مع عمليات تشغيلية فقط.
- viewer: قراءة فقط ضمن النطاق المعتمد.
- admin: صلاحيات إدارية واسعة، مع حماية آخر مدير نشط، وتسجيل تدقيق للعمليات الحساسة. لا يعني ذلك تجاوز التحقق من وجود الكيان أو سلامة الانتقال.

## 4. الحالة البرمجية الحالية

- AuthorizationContext موجود ويحتوي المستخدم والإذونات ومجموعتي المكاتب والمستودعات.
- build_authorization_context يعيد التحقق من الحساب النشط.
- require_permission وrequire_office_scope وrequire_warehouse_scope وrequire_transfer_scope تفرض المنع الافتراضي والتحقق من طرفي النقل.
- build_role_baseline_context يمنح baseline محافظاً للمدير فقط. بقية الأدوار، بما فيها الأدوار المقترحة، لا تحصل على grants أو نطاقات ضمنية.
- لا توجد حالياً علاقات persisted grants للمستخدمين بالمكاتب والمستودعات، ولا ينبغي توليدها من الواجهة.
- لا تعتبر الواجهات متكاملة end-to-end لمجرد وجود هذه الخدمات؛ يجب ترحيل كل service caller والتحقق منه واختباره.

## 5. تصميم قاعدة البيانات — غير منفذ

بعد مراجعة المخطط الحالي واعتماد المستخدم فقط، يمكن دراسة جداول ربط مثل:
- user_offices(user_id, office_id) بمفتاح مركب وفهارس وقيود FK.
- user_warehouses(user_id, warehouse_id) بمفتاح مركب وفهارس وقيود FK.
- جدول grants مستقل عند الحاجة لصلاحيات استثنائية محددة، مع منشئ المنحة وتاريخها وسببها.

قبل أي migration يجب التحقق من أنواع المفاتيح الفعلية، سياسات الحذف، التكرار، حسابات المديرين الحاليين، وخطة rollback. لا تنفذ هذه الوثيقة أي SQL.

## 6. خطوات الاختبار والتشغيل محلياً

من جذر المستودع:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\\Scripts\\Activate.ps1
# macOS / Linux:
# source .venv/bin/activate

python -m pip install -r python_app/requirements.txt pytest
python -m compileall -q python_app
python -m pytest python_app/tests
```

لتشغيل اختبارات التفويض وحدها:

```bash
python -m pytest python_app/tests/test_authorization.py python_app/tests/test_authorization_policy.py -q
```

لا تستخدم قاعدة بيانات الإنتاج للاختبارات. الاختبارات هنا تنشئ SQLite مؤقتاً داخل الذاكرة.

## 7. ضوابط ما قبل الإنتاج

- حماية آخر مدير نشط من التعطيل أو الحذف أو خفض الدور.
- رفض الصلاحية عند غياب أي grant أو عند تعذر تحميل grants.
- فحص المصدر والوجهة والمستودع المرتبط في كل نقل.
- منع الوصول المباشر إلى المرفقات والتقارير خارج النطاق.
- تدقيق تغييرات الأدوار والمنح والاعتمادات والتصدير والاستعادة.
- اختبارات سلبية لكل عملية ولكل دور، واختبارات تكامل تثبت أن كل مسارات الواجهة تمر عبر الخدمات المفوضة.
- لا تُفعّل الأدوار الجديدة ولا تغيّر قاعدة البيانات قبل مراجعة المخطط وموافقة صريحة.
